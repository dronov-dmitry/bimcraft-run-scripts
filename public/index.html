Release notes

Where the files go

BIMCraft reads plugins at start-up. There is no in-application install button and no silent update: this page only delivers files.

Linux ${XDG_CONFIG_HOME:-~/.config}/bimcraft/plugins
macOS ~/Library/Application Support/BIMCraft/plugins
Windows %APPDATA%\BIMCraft\plugins
Override BIMCRAFT_PLUGINS (an empty value disables plugins)

Restart BIMCraft after installing. The Plugins window lists what loaded and what was refused, with the reason.

What this protects, and what it does not

  • The digest is served by the same service that serves the archive, so it protects against a broken download, a proxy or a tampered CDN — not against the publisher.
  • BIMCraft itself does not sign or verify plugins. Installing a plugin is a decision to run its code with the permissions its manifest asks for.
  • The plugin runs inside the WebAssembly sandbox: no files or network unless the host grants them, with memory and time limits. That is a limit on accidents, not a security boundary against a targeted attack.
